# ภาพรวมและสถาปัตยกรรมระบบ Turbo Indicators v2

เอกสารนี้รวบรวมฟีเจอร์ โครงสร้างไฟล์ หน้าที่การทำงานของแต่ละส่วน และความเชื่อมโยงกันภายในโปรเจกต์ (Deriv Auto Trading Dashboard)

---

## 🌟 ฟีเจอร์ทั้งหมดของระบบ (System Features)

1. **ระบบเทรดอัตโนมัติบนแพลตฟอร์ม Deriv (Auto Trading Bot):** ระบบสามารถเปิดและปิดออเดอร์อัตโนมัติตามกลยุทธ์ที่ได้ตั้งค่าไว้ โดยเชื่อมต่อกับ Deriv WebSocket API โดยตรง
2. **รองรับการเทรดหลายสินทรัพย์พร้อมกัน (Multi-Asset Concurrency):** สามารถเลือกเทรดหลายๆ คู่ (เช่น vol10, vol25, vol50_1s เป็นต้น) ในเวลาเดียวกัน โปรแกรมจะแยกการทำงาน (Spawn) ออกเป็นบอทอิสระต่อสินทรัพย์
3. **ระบบวิเคราะห์อินดิเคเตอร์แบบประสิทธิภาพสูง (High-Performance Stateful Analysis):** คำนวณอินดิเคเตอร์เชิงเทคนิค เช่น EMA (Short, Medium, Long), Wilder's ATR, MACD, RSI, และ Choppiness แบบเรียลไทม์ โดยใช้การประมวลผลอัลกอริทึม O(1) และชุดคำสั่งระดับฮาร์ดแวร์ SIMD (AVX2) เพื่อความรวดเร็วสูงสุด ลดภาระหน้าจอ และได้ผลลัพธ์ที่แม่นยำ
4. **กลยุทธ์ตามรูปแบบแท่งเทียน (Candlestick Spike Strategy):** ตรวจจับจังหวะการเปลี่ยนผันหรือแท่งเทียนที่มีการกระชาก (Spikes) นอกขอบเขตของ ATR ปกติ และทำการเข้าซื้อหรือขายในจุดเริ่มต้นของแท่งเทียนใหม่ (วินาทีที่ :00) โดยคำนวณและทำธุรกรรมให้เสร็จทันเวลาก่อนแท่งเทียนจะจบลง
5. **ระบบบริหารจัดการเงินแบบมาร์ติงเกลและจุดตัดขาดทุน (Martingale & Max Loss Cutoff):** ระบบติดตามผลแพ้ชนะ หากเกิดการขาดทุน (Loss Streak) จะสามารถใช้เซ็ตค่าของยอดเงินที่ซ้อนทับกันเป็นชุด (List) เพื่อคำนวณปริมาณการลงทุนในไม้ถัดไปแบบอัตโนมัติ พร้อมระบบความปลอดภัย **MaxLossCon** เพื่อตัดจบ (Give Up) รอบการทบไม้หากขาดทุนติดต่อกันถึงลิมิตที่กำหนดไว้
6. **ตั้งเวลาเทรดอัตโนมัติพร้อม UI อัจฉริยะ (Automated Scheduling & Smart UI):** ฟังก์ชั่นกำหนดช่วงเวลา (Date Range) ในการเปิดบอท และ หยุดบอทล่วงหน้า พร้อมลูกเล่น UI เปลี่ยนสีพื้นหลังแผงหน้าจอ (Cool Blue) เมื่อระบบกำลังทำงานตามรอบเวลา และปิดการทำงาน Schedule อัตโนมัติเมื่อหมดเวลา รวมถึงสามารถหยุดระบบเมื่อเงื่อนไขบรรลุเป้า (Condition Stop Trade)
7. **ระบบแจ้งเตือนแบบเรียลไทม์ (Telegram Notifications):** ผูกบอท Telegram สำหรับรายงานผลเมื่อระบบเริ่มต้นเทรด หยุดเทรด ชนลิมิต MaxLossCon และทุกครั้งที่มีการชนะหรือแพ้ในแต่ละไม้ พร้อมสรุปกำไรสะสมและยอดคงเหลือ 
8. **แดชบอร์ดบริหารส่วนกลาง (Interactive Dashboard):** หน้าต่าง UI ส่วนกลางสำหรับปรับแต่งค่าพารามิเตอร์ของอินดิเคเตอร์ สลับโทนสี เปลี่ยนสินทรัพย์ พร้อมด้วยกราฟที่วาดเส้น Technical Analysis เพื่อให้ดูข้อมูลย้อนหลัง และสถานการณ์ปัจจุบันได้อย่างสมบูรณ์แบบ
9. **ระบบบันทึกประวัติการเทรดอัตโนมัติ (Historical Data Logging):** มีการบันทึกสถานะแท่งเทียนและการเข้าเทรดของแต่ละคู่ลงไปในไดเรกทอรีย่อยที่แบ่งไว้ตาม เดือน/วัน/สินทรัพย์ อย่างเป็นระเบียบ (JSON Format) ไว้สำหรับดึงกลับมาวิเคราะห์ใหม่
10. **ระบบเปรียบเทียบกลยุทธ์ A/B Testing (Strategy Comparison Dashboard):** แท็บวิเคราะห์ข้อมูลแบบเรียลไทม์เพื่อเปรียบเทียบประสิทธิภาพการทำนายแท่งเทียน (Next Color) ระหว่าง 4 กลยุทธ์ (V1, V2, V3A, V3B) พร้อมระบบ Filter ตามสินทรัพย์และการคำนวณ Max Loss Streak

## 📁 ไฟล์ทั้งหมดและหน้าที่การทำงาน (Files & Responsibilities)

ระบบถูกออกแบบโดยแยกเป็นส่วนการคำนวณหลักด้วย **Rust** (Backend & Calculation Engine) และส่วนหน้าบ้านด้วย **HTML/JS** (Dashboard)

### ส่วนของ Backend (Rust - `/src/`)
* **`main.rs`** 
  - เป็นหัวใจหลักในการรันเปรียบเสมือนสมองจัดการเซิร์ฟเวอร์ โดยใช้ `axum` และ `tokio` 
  - ทำหน้าที่เปิด Web Server จัดการเส้นทาง API Endpoint (เช่น `/api/trade`, `/api/stop`, `/api/getStrategyComparison`) จัดไฟล์หน้าบ้าน (ServeDir) คอยรอรับคำสั่งแก้ไฟล์ระบบปฏิบัติการ (`setup.json`) 
  - สร้าง WebSocket Server เพื่อกระจายข่าวสาร (Broadcast) แบบเรียลไทม์ไปยังหน้าเว็บ
  - ควบคุมการทำงานของบอท โดยหากมีออเดอร์ให้ไป spawn การทำงานที่ `deriv.rs`
* **`deriv.rs`**
  - เป็นโมดูลรับผิดชอบการเชื่อมต่อตรงข้ามกับ Deriv ผ่าน WebSocket 
  - รับหน้าที่ตั้งแต่กระบวนการ Authorize, ร้องขอแท่งเทียนย้อนหลัง (Ticks History), สตรีมแท่งเทียนปัจจุบันแบบ Live 
  - ทำการส่งแท่งเทียนให้ `AnalysisEngine` และเอาคำตอบมาพิจารณา 
  - สั่งส่งคำสั่งซึ้อขาย (Buy Request) หากถึงวินาที `:00` และติดตามผลสำเร็จ/แพ้ (Proposal Open Contract) เพื่อใช้ตรรกะ Martingale
  - มีระบบตรวจสอบขีดจำกัด `MaxLossCon` และบันทึกสถานะแท่งเทียนว่ายอมแพ้ (`gaveUp`) ลงไปใน JSON ทันทีเมื่อเกิดการตัดรอบเพื่อความปลอดภัย
* **`analysis.rs`**
  - เป็นเอ็นจินผู้รับบทวิเคราะห์ (Stateful Analysis Engine) 
  - รวมการทำงานของอินดิเคเตอร์เข้ากับแท่งเทียน OHLCV แทนที่จะคำนวณทุกแท่งแสนๆ แท่งใหม่ (O(n)) เอ็นจินนี้จะจำตัวแปรสถานะชั่วคราวไว้ และคำนวณเฉพาะผลต่างของแท่งใหม่ (O(1)) เท่านั้น 
  - ใช้ช่วยยืนยันสัญญาณเทรดเช่น Spike เกิดขึ้นหรือไม่ หรือ EMA ชี้ไปทางไหน
* **`indicators.rs`**
  - แหล่งรวมสูตรคำนวณคณิตศาสตร์สำหรับบรรดาเครื่องมือเทคนิคต่างๆ (HMA, MACD, RSI, Choppiness Index, ATR) 
  - เขียนในรูปแบบชุดโครงสร้างเชิงคณิตที่ใช้ Cache-Optimized Implementation รวมถึงมีโค้ดเปรียบเทียบ Baseline ให้เห็นความโปร่งใส
* **`simd.rs`**
  - แหล่งรวมคำสั่งคำนวณเวกเตอร์ในระดับฮาร์ดแวร์เพื่อเพิ่มประสิทธิภาพทวีคูณ (SIMD-Optimized) เช่น `sum_f64_avx2`, `ema_update` (คณิตศาสตร์ Inline ข้อมูลเพื่อให้ไม่มีหน่วง)
* **`get_action.rs`**
  - ตรรกะช่วยตัดสินใจ ว่าจะสั่งซื้อ/ขาย หรือรอคอย (Call / Put / Wait)
  - โดยเอากฎพื้นฐานของการตามติดสัญญาณ (Spike Detection และ สีของแท่งเทียนที่จบ) ควบคู่กับประวัติว่าเสียติดต่อกันมาดี่รอบแล้ว (`loss_con`) เพื่อคำนวณสีไม้ต่อไปเสมือนการเล่นเกณฑ์จากระบบในรุ่นก่อน
* **`streaming.rs`**
  - โมดูลตัวจัดการ Ring Buffer หรือระบบหน่วยความจำวน สำหรับการรับแท่งเทียนแบบเรียลไทม์และสตรีมเพื่อเอาดัชนีส่งต่อไปใช้
* **`lib.rs`**
  - ตัวโชว์ระดับไลบรารีของแกนหลัก รวมถึงสร้าง Struct หลักๆ เช่น `OHLCV` และ `PriceBuffer` ที่ใช้ตรงกันทั่วถึง

### ส่วนโครงสร้างจัดการและ Frontend (Web & Configs)
* **`public/index.html`**
  - หน้าจอโต้ตอบกับผู้ใช้จริง (Frontend GUI) นำเสนอให้เห็นเป็นภาพแดชบอร์ด 
  - เป็นไฟล์ที่บรรจุทั้ง HTML layout, CSS themes, และ Javascript ไว้เต็มประสิทธิผล (สามารถเชื่อมต่อ Rust WebSocket, คุมบอท, แท็บกราฟ, แท็บ Analysis Data, และแท็บ Strategy Comparison สำหรับ A/B Testing)
* **`public/clsATRCandleAnalyzer.php`**
  - (แฟ้มย้อนหลัง) เป็นตัวคลาสทางคณิตศาสตร์สไตล์เก่า (Legacy Code) ใช้เป็นแม่พิมพ์สำหรับการโยกตรรกะฝั่ง PHP เข้าสู่งานในฝั่ง Rust
* **`setup.json`**
  - พื้นที่เก็บข้อมูลการคอนฟิก (State Memory) ของหน้าเว็บ เพื่อให้ Backend รู้ว่าตอนนี้ตัวเลือกทางเทคนิค ตรรกะคุมทุน โทนสี สินทรัพย์ที่เลือกคืออะไร แม้ระบบรีเซ็ตก็ยังจำค่านี้ได้
* **`tradeData/ (Directory)`**
  - อาณาจักรที่เกิดจากการที่โปรแกรม Auto-generate โฟลเดอร์รายเดือนและรายวัน ตลอดจนสินทรัพย์ คอยเก็บไฟล์ `trades.json` ของล็อกแพ้ชนะตลอดประวัติเพื่อให้ผู้ใช้นำไปพิจารณาเป็นกราฟหรือโหลดกลับมาวิจารณ์ผลงาน
* **`Cargo.toml` และ ไฟล์ .env**
  - `Cargo.toml`: ระบบติดตั้งแพ็คเกจโครงสร้าง Rust
  - `.env`: ไฟล์ตั้งค่ากุญแจสำคัญเช่น โทเค็น (API Token), รหัสแอปพลิเคชัน (App ID) และกุญแจ Telegram สำหรับแชทบอท

## 🔄 การเชื่อมโยงและการไหลของข้อมูล (Architecture & Data Flow)

กระบวนการทำงานถูกซิงโครไนซ์เพื่อให้ไร้รอยต่อดังนี้:

1. **User Interaction:** ผู้ใช้เข้าผ่านบราวเซอร์โหลด `index.html` แล้วตั้งค่าพารามิเตอร์ อินดิเคเตอร์และกลยุทธ์ กดอัพเดตค่า
2. **Config Preservation:** หน้าเว็บยิง `POST /api/setup` พร้อมข้อมูล JSON ทำให้ `main.rs` รับมาเซฟทับเป็นค่าใหม่ที่ `setup.json`
3. **Triggering Engine:** ทันทีที่ผู้ใช้กดปุ่ม **"Start Trading"** (หรือเมื่อถึงกำหนดวันที่ตัังใน Auto Schedule) 
   - ฝั่งเว็บจะ Request ไปสู่ `POST /api/trade` แจ้งว่าเริ่มได้
   - `main.rs` ได้รับหน้าที่แล้ว จะเริ่มเข้าสู่กระบวนการ **Spawn** โดยแยกเธรดเปิดบอทเชื่อมต่อ Deriv API อิสระผ่านโมดูล `deriv.rs` เท่ากับจำนวนคู่สินทรัพย์ (Assets) ที่ผูกเอาไว้
4. **Data Sourcing & Tracking:** ภายใน `deriv.rs` จะเริ่มสร้าง Socket Connection ส่ง Auth Token ไปเบิกทางและแจ้งความจำนงติดตามกราฟแท่งเทียน (Ticks History) จาก Deriv
5. **Turbo Indicator Processing:**
   - มวลแท่งเทียนที่หลั่งไหลเข้ามา จะถูกนำส่งเข้า `analysis.rs` (AnalysisEngine) ทันที
   - เอนจินใช้โมดูลขั้นเทพที่เขียนดักใน `indicators.rs` และ `simd.rs` ทำให้คำนวณและตอบการกระชากของราคา (Spike) กลับออกมาระดับศูนย์เสี้ยววินาที 
6. **Decision & Action:**
   - หากแท่งเทียนวิ่งจบจังหวะที่กำหนด (`:59` น. ที่เสี้ยววินาทีนั้นๆ) `deriv.rs` จะวิ่งเช็คว่า Spike ตรงเงื่อนไขหรือไม่
   - หากใช่ ส่งให้ `get_action.rs` สรุปสถานการณ์ Call/Put หรือตามหลักพัลส์ต้านทาน
   - ลั่นคำสั่ง `buy` ทันทีในวินาทีที่ `:00` แจ้งรหัสเข้ากับโบรเกอร์ 
   - พร้อมพิมพ์ใบเสร็จผ่าน Telegram แจ้งเจ้าของทันควัน
7. **Money Management Return:** 
   - เมื่อสัญญาเทรดแต่ละไม้จบลง (Duration end) ระบบได้รับการคำนวณ profit หากชนะจะรีเซ็ตลำดับ แต่ถ้าแพ้ (`profit <= 0`) ฝั่ง `deriv.rs` สั่งนับ `loss_con` เพิ่มขึ้นและวิ่งกลับเข้าสู่ Martingale list เตรียมตัวเข้าซื้อไม้ถัดไปตามโควตาที่ต้องจ่าย
8. **Real-time Feedback loop (Logs & GUI):** 
   - ทุกครั้งที่ `deriv.rs` ตรวจเจอยอด Tick ใหม่ ค่าการคำนวณต่างๆ จะถูกสะท้อนกลับเป็น Message ผ่าน Broadcast Channel 
   - ส่งออกสู่บราวเซอร์ให้ `index.html` นำข้อมูลไปวาดลงบน UI Dashboard ทำให้กราฟแท่งใหม่และสัญญาณไฟวิ่งสว่างแบบสดใหม่ทุกวินาที 
   - และทิ้งรอยเท้าบันทึกในระบบโฟลเดอร์ `tradeData/` เพื่อเก็บเป็น Data Warehouse แบบเงียบๆ และมีประสิทธิภาพ
