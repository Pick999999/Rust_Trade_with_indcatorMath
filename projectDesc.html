อธิบายกลไกการส่งผ่านข้อมูลใน Project

1. ทำไม Rust ถึงไม่มี Global Variable ในโปรเจกต์นี้?

ภาษา Rust ถูกออกแบบมาให้เน้นความปลอดภัยของหน่วยความจำ (Memory Safety) และความปลอดภัยในการทำงานแบบพร้อมกันหลายเธรด (Concurrency Safety) การใช้ Global Variable แบบที่แก้ไขค่าได้ (Mutable Global State เช่น static mut) ถือเป็นความเสี่ยงอย่างมาก (Unsafe) และอาจทำให้เกิดปัญหา Data Race หรือข้อมูลพังเมื่อถูกเข้าถึงพร้อมกันหลายจุด

วิธีแก้ปัญหาของ Rust (และ Web Framework อย่าง Axum): แทนที่จะประกาศตัวแปรไว้ลอยๆ (Global) โปรเจกต์นี้ใช้กลไกที่เรียกว่า Shared State โดยประกาศโครงสร้างข้อมูล AppState ที่ถูกห่อหุ้มด้วย Arc<Mutex<T>> หรือช่องทางสื่อสาร broadcast::Sender

Arc ช่วยจัดการวงจรชีวิตของตัวแปร ส่วน Mutex ช่วยล็อกข้อมูลเวลาอ่านเขียนไม่ให้ชนกัน จากนั้นส่งผ่านตัวแปรนี้เข้าไปในแต่ละฟังก์ชัน (Handler) ผ่านระบบของ Axum คือ State(state): State<AppState> ทำให้การแชร์ข้อมูลปลอดภัยและมีประสิทธิภาพ

2. กลไกการส่งผ่านข้อมูลจากหน้าเว็บ (index.html) ไปยัง Rust Backend

ขอยกตัวอย่างการส่งรายชื่อ Asset List จากหน้าเว็บไปยัง Backend ว่ามีกระบวนการอย่างไร

ขั้นตอนที่ 1: ฝั่ง Frontend (JavaScript ใน index.html)

เมื่อผู้ใช้คลิกปุ่ม "Go Trade" (ปุ่มที่มี ID เป็น goTradeBtn) ตัว JavaScript จะเริ่มทำงานดังนี้:

  1. เรียกใช้งานฟังก์ชัน collectSettings() ซึ่งมีหน้าที่รวบรวมข้อมูลทั้งหมดที่ผู้ใช้กรอก โดยรายชื่อ Asset จะถูกอ่านจาก Checkbox ผ่านคำสั่งนี้:
    const assets = [...document.querySelectorAll('input[name="asset"]:checked')].map(cb => cb.value);
  2. นำข้อมูลรวมกันเป็น JSON Object (ตัวแปร settings) แล้วใช้ฟังก์ชัน fetch() ส่ง HTTP Request แบบ POST ไปที่ Endpoint ของ Rust Backend คือ /api/trade: 
    const response = await fetch('/api/trade', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(settings)
});

ขั้นตอนที่ 2: ฝั่ง Backend (Rust ใน src/main.rs)

ในฝั่ง Rust มีการผูก Route ของ /api/trade ไว้ให้เรียกใช้งานฟังก์ชัน handle_post_trade ทันทีเมื่อมี Request เข้ามา

ฟังก์ชันนี้จะรับข้อมูล JSON ที่ส่งมาจากหน้าเว็บอัตโนมัติ ผ่าน Extractor ที่ชื่อว่า Json() โดยจะแปลงข้อมูล (Deserialize) จาก JSON String ให้กลายเป็นโครงสร้าง (Struct) ของ Rust ที่ชื่อ AppConfigPayload

async fn handle_post_trade(
    State(state): State<AppState>,
    Json(payload): Json<AppConfigPayload>,
) -> Json<serde_json::Value>

ภายใน Struct AppConfigPayload มีการเตรียมฟิลด์สำหรับรับรายชื่อ Asset เอาไว้แล้ว:

pub struct AppConfigPayload {
    // ... ฟิลด์อื่นๆ
    pub assets: Vec<String>,
    // ...
}

จากจุดนี้ ข้อมูลรายชื่อ Asset ที่ผู้ใช้เลือกจะถูกเก็บอยู่ในตัวแปร payload.assets

ขั้นตอนที่ 3: การนำตัวแปรไปใช้งานต่อในฟังก์ชันอื่นๆ

ภายในฟังก์ชัน handle_post_trade ระบบจะนำตัวแปร payload.assets ไปทำงานต่อเนื่องดังนี้:

  1. สร้าง State ย่อยสำหรับแต่ละ Asset: ระบบจะใช้ลูป for วนตามรายชื่อ payload.assets.iter() เพื่อสร้างตัวแปรสัญญาณ (AtomicBool) เตรียมไว้สำหรับคุมการทำงานของแต่ละ Asset แล้วเก็บลงใน Global Shared State (state.overtime_signals)
  2. ส่งต่อไปยังฟังก์ชันการเทรด: ตัวแปรรายชื่อ Asset จะถูกทำสำเนา (Clone) ไปยังตัวแปรชื่อ spawned_assets และ assets จากนั้นระบบจะสร้างเธรดการทำงานใหม่ (tokio::spawn) เพื่อเรียกใช้ฟังก์ชัน deriv::start_deriv_bot_multiplexed() โดยส่งตัวแปร assets เข้าไปเป็นพารามิเตอร์ เพื่อบอกให้บอทเริ่มดึงข้อมูลและเทรดเฉพาะ Asset เหล่านั้น
let handle = tokio::spawn(async move {
    // ส่งผ่าน assets และ config อื่นๆ เข้าไปในฟังก์ชันของไฟล์ deriv.rs
    if let Err(e) = deriv::start_deriv_bot_multiplexed(
        app_id, api_token, account_id, config, assets, tx, cmd_rx, ot_signals
    ).await {
        eprintln!("Multiplexed bot crashed: {}", e);
    }
});
